AUDIO SYSTEM CLASS DESIGN
=========================

Class:

    AudioSystem

Purpose:

    Own the audio backend, mixer buses, spatial emitters, streaming music, and
    smoothed parameters driven by sailing and weather simulation.

Public API:

    Result<AudioHandle,AudioError> Play(const AudioEvent& event);
    Result<void,AudioError> Stop(AudioHandle handle, DurationSeconds fade);
    void SetListener(const ListenerState& listener);
    void UpdateEmitter(AudioHandle handle, const EmitterState& emitter);
    void SetParameter(AudioHandle handle, AudioParameter id, float value);
    void SetBusVolume(AudioBus bus, float normalizedVolume);
    void Update(RealDeltaSeconds);

Buses:

    Master
    Music
    Environment
    Vessel
    Interface
    Voice

Emitter data:

    WorldPosition and SI velocity metres/second.
    Minimum/maximum distance.
    Gain and pitch.
    Loop state.
    Occlusion.
    Event parameters.

Sailing parameters:

    Vessel speed.
    Wave impact.
    Hull stress.
    Sail luffing.
    Rope tension.
    Wind intensity.
    Rain intensity.
    Camera underwater fraction.

Behavior:

    Smooth simulation values before applying them.
    Stream large music/ambience assets.
    Virtualize inaudible emitters.
    Apply underwater filtering.
    Update listener from interpolated camera transform.
    Stop emitters automatically when owning entities die.

Rules:

    Audio callback performs no allocation or blocking I/O.
    Handles are generation checked.
    Missing clips produce explicit failures or configured fallback silence.
    Simulation systems publish values; they do not call backend APIs directly.
    The real-time callback consumes only a prepared bounded AudioFrame: no
    allocation, lock, I/O, logging, service calls, or exceptions.

Tests:

    Play/stop handle lifecycle.
    Stale handle rejection.
    Distance attenuation.
    Parameter smoothing.
    Bus gain hierarchy.
    Streaming underrun handling.
    Entity destruction removes emitters.

Dependencies:

    AssetManager
    AudioFrameBuilder/control snapshots
    Optional UnderwaterAcoustics transfer snapshot

Canonical integration contract:

    Normative owner of audio device/backend, buses, AudioHandle voices/streams,
    and callback buffers. Entity/weather/vessel/ocean/camera systems publish P12
    AudioEvent/Listener/Emitter values with EntityId, WorldPosition, SI velocity,
    TickId, and generation; AudioSystem does not depend on or call those owners.
    The off-callback builder resolves AssetId and spatial/acoustic state.

    Stale handles, missing clips, stream underrun, capacity, and backend/device
    failures return AudioError/status. Explicit fallback silence is Degraded,
    never a ready missing clip. On callback underrun reuse the last bounded
    frame and set atomic telemetry only. See ..\FRAME_THREADING_MODEL.txt,
    ..\ERROR_RESULT_POLICY.txt, and ..\ocean\84_underwater_acoustics.txt.
