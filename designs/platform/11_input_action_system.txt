INPUT ACTION SYSTEM CLASS DESIGN
================================

Class:

    InputActionSystem

Purpose:

    Convert raw GLFW/gamepad input into named gameplay actions with current,
    previous, pressed, released, and analog values.

Public API:

    void BeginFrame();
    void ProcessEvent(const InputEvent& event);
    void EndFrame();
    ActionValue Get(ActionId action) const;
    bool Pressed(ActionId action) const;
    bool Released(ActionId action) const;
    void PushContext(InputContextId context);
    void PopContext(InputContextId context);
    void Rebind(ActionId action, InputBinding binding);
    InputActionSnapshot SnapshotForTick(TickId tick) const;

Initial actions:

    Steer
    SailTrim
    RaiseSail
    LowerSail
    DropAnchor
    CameraLook
    CameraZoom
    Interact
    Pause

Binding types:

    Keyboard key.
    Mouse button.
    Mouse axis.
    Mouse wheel.
    Gamepad button.
    Gamepad axis.
    Composite positive/negative digital axis.

Processing:

    Buffer GLFW callbacks as InputEvents.
    Apply active input contexts by priority.
    Apply dead zones and response curves.
    Combine bindings according to action policy.
    Clamp normalized action values.
    Calculate pressed/released transitions.

Rules:

    Raw callbacks do not directly control vessels.
    UI context can consume input before gameplay context.
    Rebinding rejects reserved/invalid inputs.
    Bindings serialize independently from save games.
    Simulation consumes command snapshots, not live mutable state.

Tests:

    Press/hold/release transitions.
    Composite keyboard axis.
    Analog dead zone.
    Context priority/consumption.
    Rebinding persistence.
    Focus-loss clears stuck inputs.
    Multiple bindings combine correctly.

Dependencies:

    WindowPlatform event values
    ConfigurationSettings binding snapshot

Canonical integration contract:

    Normative input-state owner, not a gameplay/controller owner. WindowPlatform
    P0 callbacks enqueue bounded InputEvent values. Main thread applies contexts
    and UI consumption, then produces an immutable timestamped
    InputActionSnapshot. P2/P5 controllers consume the latched snapshot and
    enqueue GameplayCommands; live input is never read mid-tick.

    ActionId/InputContextId are typed IDs, analog values explicitly
    dimensionless [-1,1], and binding persistence belongs to
    ConfigurationSettings. Callback/rebind/capacity failures return InputError;
    focus loss creates explicit release values. See
    ..\CANONICAL_CONVENTIONS.txt, ..\FRAME_THREADING_MODEL.txt, and
    ..\sailing\48_player_sailing_controller.txt.
