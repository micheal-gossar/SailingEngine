OCEAN SUBSYSTEM ARCHITECTURE AND IMPLEMENTATION INDEX
=====================================================

Purpose
-------

Define the ownership, dependency direction, data contracts, and staged delivery
plan for a physically grounded ocean and marine environment. The subsystem is a
hybrid: no single representation is expected to cover deep ocean, surf zones,
vessel-scale interactions, optics, and ecology.

Public API / subsystem contract
-------------------------------

    OceanDomain::BeginPhysicsPhase(const OceanTickContext&);
    OceanDomain::SubmitCouplingOutputs(const OceanCouplingBatch&);
    OceanDomain::CompleteFixedTick();
    OceanDomain::PublishRenderSnapshot(RenderFrameId);
    OceanQueryService::SampleBatch(const OceanQueryBatch&, OceanQueryResults&);
    OceanQueryService::SubmitVisualGpuBatch(const GpuOceanQueryBatch&);
    OceanStreamingService::ApplyWorldCellPlan(const WorldCellPlan&);
    MarineEcosystemManager::SetObservers(span<const EcosystemObserver>);

Callers address water in WorldCoordinateSystem coordinates and identify the
simulation tick, query policy, and required fields. Only OceanQueryService is
allowed to combine deep, coastal, current, tide, and interaction contributions.
Consumers must not sample renderer displacement images directly.

Module map and dependency direction
-----------------------------------

    WeatherSystem / SimulationClock / TerrainSystem / WorldCoordinateSystem
                           |
                           v
                 OceanEnvironmentForcing
                    /              \
                   v                v
       DeepWaterSpectralOcean   CoastalOceanSolver <--- bathymetry tiles
                   \                /
                    v              v
                    OceanQueryService <--- OceanInteractionSystem
                         |
           +-------------+------------------+
           v             v                  v
    BuoyancySystem  MarineEcosystem   UnderwaterAcoustics

    immutable OceanRenderSnapshot
           |
           +--> OceanSurfaceRenderer
           +--> UnderwaterMediaRenderer
           +--> OceanEffectsSystem
           +--> UnderwaterHabitatRenderer

    WorldStreamingManager owns global observers/admission and supplies
    WorldCellLease plans. OceanStreamingService coordinates the ocean
    participant transaction/records inside those leases, while each producing
    module owns its resident resources. OceanValidationAndQuality
    observes every module and owns profiles, conformance tests, and quality
    policy; it does not own simulation state.

There are no render-to-simulation dependencies. GPU readback is diagnostic or
delayed non-authoritative telemetry only. Cross-queue ordering is expressed to
RenderGraph, never by ad-hoc queue waits.

The simulation dependency graph is deliberately split around vessel physics.
Ocean generation N is immutable while physics samples it. Physics then submits
tagged kinematics, impulses, and already-applied force provenance. Only after
that barrier may interaction/coastal modules advance and publish generation
N+1. This removes the apparent query -> vessel -> wake -> query same-tick cycle.
Reaction tagged for N+1 is applied once by its declared force owner.

Legacy design compatibility
---------------------------

06_ocean_simulation.txt is revised and retained only as the original high-level
OceanSimulation compatibility facade. Its public sampling role is
fulfilled by OceanDomain plus OceanQueryService, and its renderer parameters by
DeepWaterSpectralOcean snapshots. It must not be instantiated as an independent
sum-of-waves implementation beside modules 72-76. Its promises of deterministic
sampling, fixed simulation time, analytic derivatives, and CPU/GPU comparison
remain requirements; any narrower API adapter delegates to the new owners.

Key data structures
-------------------

OceanTick identifies an integer fixed tick and rational tick period.
OceanEpoch fixes seed, spectrum epoch, tide epoch, and world-coordinate datum.
OceanRenderSnapshot is immutable and generation-tagged; it contains only handles
or compact parameters, never pointers into mutable module storage.
OceanCellKey uses signed integer cell coordinates plus a layer/LOD.
OceanResult carries a validity mask, source-generation tuple, and confidence.
All public values obey 87_ocean_conventions_invariants.txt; implicit unit,
vertical datum, direction, Fourier normalization, or origin conversion is an
initialization error.

Algorithms and physical models
------------------------------

Deep water uses directional JONSWAP/Phillips-family spectral energy and
Hermitian inverse FFT cascades. Intermediate water transports wave action over
bathymetry; coast tiles solve conservative depth-integrated flow, optionally
with a weakly dispersive surf-band tier. Interactions inject conservative
pressure/volume/momentum sources. Query composition follows a documented order
so current, tide, wave orbital velocity, wakes, and shoreline flow are not
double counted. Rendering derives optics/effects from physical state rather
than inventing unrelated wave fields.

Update rates, threading, and GPU ownership
-----------------------------------------

Simulation fixed tick defaults to 60 Hz. Environment forcing publishes at
1-2 Hz; coastal flow advances at 10-30 Hz with CFL substeps; ecosystem cells at
0.2-2 Hz; nearby agents at 15-30 Hz; authoritative vessel queries at 60 Hz.
Render FFT and visual effects run once per rendered frame. Job threads prepare
immutable CPU generations. The render thread owns GPU creation and RenderGraph
registration; compute/graphics queues own execution according to graph edges.

Lifecycle and dependencies
--------------------------

Create coordinate/time/terrain/weather services, then OceanDomain and its
simulation modules, then query/interaction, ecosystem/acoustics, and renderers.
Shutdown stops new queries, drains jobs, retires snapshots by GpuCompletionSet,
serializes dirty cells, and finally releases GPU generations. Relevant existing
designs are ..\core\37_simulation_clock.txt,
..\core\54_world_coordinate.txt, ..\world\09_weather_system.txt,
..\world\10_world_streaming_manager.txt, ..\world\26_terrain_system.txt,
..\rendering\03_render_graph.txt, and ..\sailing\07_buoyancy_system.txt.

Failure and error behavior
--------------------------

Invalid descriptions fail before allocation. Missing coastal/bathymetry data
returns an explicit fallback classification; deep-water fallback is allowed
offshore, never silently near land. Generation mismatch rejects or reschedules
work. GPU device loss preserves CPU simulation and invalidates render handles.
NaN/non-conservative state quarantines the affected tile and emits diagnostics;
it does not contaminate adjacent generations.

Deterministic and testing strategy
----------------------------------

Seeds, epochs, sorted cell keys, fixed ticks, and stable reduction order define
replay. Authoritative CPU paths avoid render-frame time and GPU readback.
Golden spectra, tide stations, coastal conservation cases, wake momentum tests,
origin-shift tests, save/load replay, and CPU/GPU sample conformance are required
before integration. Every snapshot records enough provenance for capture/replay.

Post-first-pass design review closure
-------------------------------------

The review found and closed five high-risk gaps: same-tick physics/wake circular
ownership is replaced by the phased N-to-N+1 schedule; force provenance prevents
double reaction; the CPU wave band is fixed from supported hull response rather
than graphics quality; coastal wave action now has a phase-resolved zero-mean
component contract; and network peers exchange epochs/inputs/checksums instead
of attempting to replicate GPU textures. Origin/generation tags and explicit
resource retirement close the remaining streaming and queue-lifetime hazards.

Performance and scalability
---------------------------

Budgets are explicit per FFT cascade, coastal cell, wake patch, ecosystem cell,
agent tier, effect pool, and GPU transient image. Work degrades by dropping
high-frequency/detail tiers, not by changing authoritative low-frequency vessel
water. Batch APIs, SoA state, clipmaps, sparse active tiles, indirect draws, and
async compute are preferred. Quality policy is centralized in file 86.

Integration points and staged implementation order
--------------------------------------------------

Stage 1: epoch, environment forcing, deterministic low-mode query path, and
flat/deep validation. Stage 2: render FFT surface and CPU/GPU conformance.
Stage 3: bathymetry wave action, coastal wet/dry solver, and shore validation.
Stage 4: buoyancy integration, conservative vessel wakes, and feedback.
Stage 5: surface optics, underwater media, caustics, and effects.
Stage 6: streaming/persistence and origin stress tests.
Stage 7: statistical ecosystem, nearby agents, habitats, and acoustics.
Stage 8: scalable quality tuning, long-run validation, and shipping profiles.
Each stage has a usable fallback and must pass file 86 metrics plus the numeric,
fault-injection, and evidence gates in 90_ocean_staged_acceptance.txt before the
next.

Engine-wide integration contract
--------------------------------

This subsystem imports the normative handle, AssetId, EntityId, WorldPosition,
SI, TickId, GpuTimelinePoint/GpuCompletionSet, Result/Error, RAII, seed, and
thread vocabulary from ..\CANONICAL_CONVENTIONS.txt,
..\FRAME_THREADING_MODEL.txt, ..\OWNERSHIP_LIFETIME_SHUTDOWN.txt, and
..\ERROR_RESULT_POLICY.txt. Ocean-specific file 87 may tighten but not redefine
those contracts. Global ownership/data-flow acceptance is in
..\INTEGRATION_ACCEPTANCE_MATRIX.txt.
