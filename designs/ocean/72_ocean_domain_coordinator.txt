OCEAN DOMAIN COORDINATOR CLASS DESIGN
=====================================

Class
-----

    OceanDomain

Purpose
-------

Own the authoritative ocean epoch, advance ocean modules in a stable order, and
publish immutable simulation/query/render generations. It is orchestration, not
a second implementation of waves or currents.

Public API
----------

    Result<void, OceanError> Initialize(const OceanDomainDescription&);
    OceanSimulationView BeginPhysicsPhase(const OceanTickContext&);
    Result<void, OceanError> SubmitCouplingOutputs(
        const OceanCouplingBatch&);
    void CompleteFixedTick();
    OceanSimulationView AcquireSimulationView(OceanTick) const;
    OceanRenderSnapshot PublishRenderSnapshot(
        RenderFrameId, double interpolationAlpha);
    OceanModuleStatus Status() const;
    void BeginShutdown();

OceanDomainDescription fixes seed, epoch, coordinate datum, maximum observers,
module quality ceilings, CPU/GPU budgets, and fallback policy. None may change
silently while a saved world is active.

Key data structures
-------------------

OceanEpoch:
    128-bit world seed, tide UTC epoch, rational simulation step, spectrum
    version, coordinate datum/version, and deterministic feature flags.

OceanGeneration:
    Tick, forcing/bathymetry/coastal/wake generations, origin generation, and
    monotonic publish sequence.

OceanOwnershipTable:
    One authoritative writer, allowed immutable readers, phase, unit/datum
    contract, fallback owner, and retirement rule for every published field.

OceanSimulationView:
    Intrusive immutable snapshot handles for forcing, deep modes, coastal tiles,
    interactions, and ecosystem environment. Destruction releases a reader
    reference; readers never lock mutable state.

OceanRenderSnapshot:
    Previous/current simulation generations, interpolation times, GPU handles,
    relative-origin transform, residency masks, and last-use GpuCompletionSet.

Algorithms and models
---------------------

The dependency order is split around PhysicsWorld. BeginPhysicsPhase latches
weather/terrain/streaming inputs and returns immutable generation N. Buoyancy
and hydrodynamics sample only N while PhysicsWorld integrates vessels. The
physics phase emits an OceanCouplingBatch containing post-step kinematics,
volume/momentum sources, external impulses, and force-owner provenance.
SubmitCouplingOutputs accepts it once. CompleteFixedTick advances forcing,
coastal CFL steps and interaction wakes from N to N+1, schedules any reaction
owned by ocean coupling for physics tick N+1, runs ecosystem/acoustic source
jobs, and atomically publishes N+1. No producer may mutate N or query N+1 while
it is under construction.

Deep spectral phases are evaluated from epoch plus tick and do not accumulate
floating-point phase. Render interpolation evaluates time-continuous spectral
phases but interpolates conservative coastal state between completed snapshots.

The composition contract is unique: mean sea level and tide establish datum;
depth-integrated currents set base velocity; deep wave displacement/orbital
velocity applies where blending masks allow; coastal wave/flow replaces, rather
than adds to, overlapping deep energy; interaction perturbations add last with
zero-mean/momentum accounting.

Update rates, threading, and GPU ownership
-----------------------------------------

The three phase calls run on the simulation coordinator at 60 Hz with an
explicit PhysicsWorld barrier between begin and submit.
Module work may fan out to JobSystem but must join before its generation is
published. The coordinator never records Vulkan commands. Render-thread code
resolves snapshots to GPU resources and registers passes; compute images remain
owned by their producing renderer/simulator and retire through FrameManager's
central queue after their GpuCompletionSet.
At most two simulation generations and configured in-flight render references
remain resident.

The coordinator enforces the ownership table: EnvironmentForcing owns mean
datum/tide/base current, CoastalOceanSolver owns nearshore mean flow/setup,
DeepWaterSpectralOcean owns offshore wave modes, InteractionSystem owns
perturbations/source ledger, QueryService owns composition only, and renderers
own no physical state. Units, axes, generation and force invariants come from
87_ocean_conventions_invariants.txt. GPU execution/lifetimes come exclusively
from 88_ocean_gpu_execution_sync.txt.

Lifecycle and dependencies
--------------------------

Construct after SimulationClock, WorldCoordinateSystem, WeatherSystem,
TerrainSystem, WorldStreamingManager, and JobSystem. Construct
OceanQueryService and render/effect/ecosystem consumers after Initialize.
Destroy consumers first. BeginShutdown rejects registrations, waits for module
jobs, publishes a terminal snapshot, asks persistence to flush dirty state, and
defers GPU retirement without calling vkDeviceWaitIdle.

See ..\core\37_simulation_clock.txt, ..\core\29_job_system.txt,
..\core\54_world_coordinate.txt, ..\world\10_world_streaming_manager.txt,
..\vulkan\20_frame_manager.txt, and 85_ocean_streaming_persistence.txt.

Failure and error behavior
--------------------------

Errors include InvalidDescription, DependencyUnavailable, EpochMismatch,
ModuleGenerationMismatch, BudgetExceeded, TickOrderViolation,
DuplicateCouplingSubmission, ForceOwnerConflict, SnapshotInUse, and
ShuttingDown. Initialization is transactional. A failed optional visual
module is omitted with a capability bit. A failed authoritative forcing,
coastal, query, or interaction module freezes its last valid generation and
marks affected results degraded; it never substitutes untagged visual data.
Fatal non-finite state captures provenance and prevents publication.

Deterministic and testing strategy
----------------------------------

Use integer ticks, rational rates, stable sorted module/cell order, seeded
counter-based RNG streams, and fixed reduction trees. Tests verify module order,
phase-order rejection, exactly-once coupling submission/reaction, snapshot
immutability, no partial publication, interpolation endpoints, dropped
render frames, catch-up ticks, shutdown with in-flight snapshots, device loss,
save/restore epoch checks, and bitwise replay on a supported CPU build. A
recorded provenance manifest makes cross-platform tolerance replay possible.

Performance and scalability
---------------------------

Snapshots use handles and copy-on-write page generations, not full state copies.
Jobs batch by Morton-sorted cell key. Publication is one atomic pointer exchange.
Back-pressure rejects optional render work before authoritative ticks miss their
deadline. Instrument per-module wait, job fan-out, snapshot lifetime, memory,
and stale generation rejects. Quality changes occur only at safe boundaries.

Integration points
------------------

ApplicationHost invokes the fixed-tick API. BuoyancySystem, hydrodynamics,
navigation, particles, and AudioSystem consume OceanSimulationView or
OceanQueryService. Renderer consumes OceanRenderSnapshot through RenderGraph.
DebugDiagnostics receives structured module/tile state without controlling it.
SaveSystem stores epoch/module metadata by consuming OceanStreamingService's
registered immutable save fragment; neither service owns the other.

Engine-wide integration contract
--------------------------------

Normative ocean composition owner at P5/P9. It consumes root TickId,
FixedDelta, WorldPosition, Result/Error, seed, ownership, and snapshot rules;
it is a WorldStreaming participant and SaveSystem state provider, not owned by
either consumer. See ..\FRAME_THREADING_MODEL.txt,
..\CANONICAL_CONVENTIONS.txt, and ..\OWNERSHIP_LIFETIME_SHUTDOWN.txt.
