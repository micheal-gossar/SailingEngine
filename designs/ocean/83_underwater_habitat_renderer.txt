UNDERWATER HABITAT RENDERER CLASS DESIGN
========================================

Class
-----

    UnderwaterHabitatSystem

Purpose
-------

Own streamed underwater biome/habitat state and render seabed materials, coral,
kelp, seagrass, rocks, detritus, and microfauna as ecosystem-driven, current-
responsive, scalable instances aligned to authoritative bathymetry.

Public API
----------

    Result<void, HabitatError> ActivateCell(
        OceanCellKey, const HabitatCellDescription&);
    void DeactivateCell(OceanCellKey);
    HabitatSnapshot AcquireSimulationSnapshot(OceanCellKey) const;
    void ApplyEcosystemDelta(const HabitatDeltaBatch&);
    void AddUpdatePasses(RenderGraphBuilder&, const OceanRenderSnapshot&);
    void AddRenderPasses(RenderGraphBuilder&, const ViewFamily&);
    HabitatStatistics Statistics() const;

Key data structures
-------------------

HabitatCellDescription contains bathymetry/material generation, substrate,
slope/aspect, depth/exposure/light/turbidity climatology, protected masks, and
procedural seed. HabitatPatch stores type (reef/coral/kelp/seagrass/sand/mud/
rock), coverage, age/health, biomass, potential-capacity inputs, disturbance,
and stable instance seed range. BenthicInstance stores cell-local transform, species/
variant, growth stage, attachment frame, animation phase, and persistence flag.
HabitatSnapshot provides suitability fields, shelter/feeding/navigation masks,
collision proxies, and ecosystem generation.

Algorithms and models
---------------------

Cook habitat suitability from substrate, slope, depth, light, temperature,
salinity, current exposure, sediment, and authored biome rules. Runtime ecology
changes patch coverage/health slowly; stable hash sampling regenerates
non-persistent instances from patch state, while rare/persistent specimens have
saved IDs. Terrain attachment uses bathymetry normal and datum; terrain version
changes reproject or invalidate instances transactionally.

HabitatPatch stores potential capacity inputs (usable m2, structural complexity,
primary-production potential, shelter and substrate limits), not final animal
population capacity. MarineEcosystemManager combines them with resources,
competition and water state and owns realized capacity/food webs. Plant/coral
biomass changes arrive as validated ecosystem deltas with carbon/biomass ledger
terms. Grazing, storm damage, sediment burial, bleaching stress, recovery and
succession are rate-limited state transitions; a visual LOD or missing mesh can
never alter habitat biomass.

Kelp and seagrass use reduced-order segmented beam motion driven by depth-varying
current and wave orbital velocity, with stiffness/buoyancy/drag by species.
GPU vertex or compute animation solves visual segments; CPU maintains only
coarse swept bounds/navigation/biomass and never treats shader motion as ecology.
Coral is static apart from small organism animation and health material changes.

Seabed shading is layered physically based substrate with wet underwater
optical response, sediment decals, benthic AO, and received energy-normalized
caustics. Geometry LOD transitions mesh instances to clusters/cards then
coverage material. Frustum/occlusion/medium-visibility culling feeds indirect
draws. Distribution is density- and seed-stable across LOD to avoid popping.

Update rates, threading, and GPU ownership
-----------------------------------------

Habitat ecology updates through MarineEcosystemManager at 0.05-0.2 Hz. CPU
attachment/bounds update on cell or terrain generation changes. GPU plant motion
runs at 15-60 Hz by distance; cull/render each frame. CPU patch/suitability state
is authoritative and saved. UnderwaterHabitatSystem owns GPU instance/animation
buffers and transfers old generations to central timeline retirement;
RenderGraph owns transient culling/draw arguments.

Lifecycle and dependencies
--------------------------

Terrain and bathymetry must be ready before habitat cell activation. Load base
description and save delta, build suitability/instances on jobs, upload a full
generation, then atomically expose it to ecosystem and rendering. Deactivation
first publishes unavailable to new agents, waits for ecosystem snapshot release,
saves dirty persistent state, and retires GPU data. See
..\world\26_terrain_system.txt, ..\rendering\42_mesh_system.txt,
..\rendering\41_material_system.txt, 75_coastal_ocean_solver.txt,
79_underwater_media_renderer.txt, and 81_marine_ecosystem_manager.txt.

Failure and error behavior
--------------------------

Errors include BathymetryGenerationMismatch, InvalidBiomeRule,
UnsupportedSubstrate, InstanceCapacity, AssetUnavailable, TerrainReprojection,
CapacityOwnershipConflict, BiomassLedgerViolation, and GpuAllocationFailed.
Missing visual assets select an explicit proxy while
preserving simulation habitat. Invalid bathymetry prevents activation rather
than floating habitats. GPU failure keeps ecosystem suitability/patch state.
Instance pressure drops smallest visual instances by stable priority, not patch
biomass or carrying capacity.

Deterministic and testing strategy
----------------------------------

Cooked rule versions, cell seeds, stable sampling, and sorted patch deltas make
regeneration deterministic. Tests cover suitability boundaries, distribution
density, no placement above seabed/inside terrain, cell seams, terrain
reprojection, kelp response and bounded deflection, stable LOD population,
ecology/visual separation, caustic energy input, origin shift, stream/save
round trip, missing assets, and device recreation.
Long-run tests exercise grazing/recovery, storm damage/succession, potential
capacity continuity at cell seams, ecosystem biomass delta closure, and
identical simulation patches under every render/animation quality tier.

Performance and scalability
---------------------------

Use hierarchical patch grids, procedural regeneration, GPU instance culling,
meshlets/indirect draws, VAT/procedural plants, clustered far geometry, sparse
suitability fields, and medium-visibility range culling. Scale instance density,
geometry/skeleton detail, plant segment count/update rate, and received caustic
detail without changing simulation patch coverage. Profile cells/patches,
instances per LOD, animation/cull/draw time, overdraw, upload bytes, and
simulation-to-visual density error.

Integration points
------------------

Terrain supplies seabed and substrate. Coastal/environment modules supply depth,
light exposure, currents, waves, temperature, and sediment. Ecosystem consumes
habitat fields and drives deltas. Marine agents consume shelter/feeding and
navigation masks. Underwater media supplies attenuation/caustics. Asset,
Mesh, Material, Animation, Renderer, Save, and Streaming systems manage their
respective resource contracts.

Engine-wide integration contract
--------------------------------

Normative owner of authoritative habitat patch/suitability state and its visual
instance generations. The class name is UnderwaterHabitatSystem despite the
historical filename. Terrain/bathymetry snapshot -> habitat generation ->
ecosystem delta is phase-separated; neither side owns the other. Global
residency remains WorldStreamingManager authority. GPU buffers are P15-only and
retire after GpuCompletionSet. See ..\CANONICAL_CONVENTIONS.txt,
..\world\INDEX.txt, and ..\OWNERSHIP_LIFETIME_SHUTDOWN.txt.
