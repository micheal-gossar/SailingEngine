OCEAN GPU EXECUTION AND SYNCHRONIZATION CLASS DESIGN
====================================================

Class
-----

    OceanGpuExecutionPlan

Purpose
-------

Declare queue ownership, pass dependencies, image/buffer states, history
generation, staging, readback latency, and retirement for all ocean GPU work so
simulation/render synchronization is explicit and free of hidden stalls.

Public API
----------

    Result<OceanGpuFramePlan, OceanGpuError> Build(
        RenderGraphBuilder&, const OceanRenderSnapshot&, const ViewFamily&);
    void RegisterProducer(const OceanGpuProducerDeclaration&);
    GpuReadbackTicket RequestDiagnosticReadback(
        const OceanDiagnosticReadback&);
    ReadbackStatus Poll(GpuReadbackTicket, OceanReadbackResult&) const;
    void Collect(const CompletedGpuTimelines&);
    OceanGpuExecutionStatistics Statistics() const;

Key data structures
-------------------

OceanGpuProducerDeclaration lists persistent resources, pass-local transients,
queue capability, exact VkPipelineStageFlags2/VkAccessFlags2/layout uses,
format/extent generations, history count, and fallback. OceanGpuFramePlan
contains pass DAG, imported resource initial/final states, cross-queue release/
acquire edge declarations, descriptor generations, origin/snapshot tuple, and
last-use resource declarations. CommandScheduler assigns queue-qualified
timeline values at submission. ReadbackSlot stores request generation, byte
range, copy-completion GpuTimelinePoint, earliest CPU frame, expiry, and
diagnostic-only purpose.

Algorithms and models
---------------------

The nominal DAG is:
    Transfer uploads forcing/bathymetry/spectrum generations.
    Async compute evolves H(k,t), performs all FFT stages, builds displacement/
        slope/Jacobian mips, updates optional visual coast/wakes/foam/bubbles,
        culls habitat/animal instances, and writes indirect arguments.
    Graphics shadow/depth/opaque terrain complete before refraction receivers.
    Compute builds waterline/froxels/caustics when their inputs are ready.
    Graphics draws ocean surface, habitats/animals, spray, transparencies.
    Compute/graphics composites underwater media and postprocesses.

RenderGraph derives barriers from declared producer/consumer uses. FFT ping-pong
stages alternate storage reads/writes with COMPUTE_SHADER storage barriers;
final fields transition once to sampled reads. Queue-family transfers emit a
release on the producer and acquire on the consumer, joined by a timeline
semaphore edge. Concurrent sharing is allowed only when profiling proves it
better and the declaration names it. Host waits, vkQueueWaitIdle, and
vkDeviceWaitIdle are forbidden in normal frames.

Persistent double/triple-buffer slots are indexed by RenderFrameId and carry
OceanGeneration plus OriginGeneration. A slot cannot be reused until every
consumer GpuCompletionSet completes. Histories require exact view, extent, snapshot,
origin, medium, and algorithm generations; otherwise the pass clears/reseeds
instead of sampling stale content. Async-compute overlap is optional: the same
DAG must remain valid when all work maps to one queue.

Diagnostic readback copies selected compact data after its last GPU producer to
a bounded staging ring. Poll returns Pending for at least the configured two or
more frame latency; it never inserts a wait. It is prohibited as an input to
OceanDomain, PhysicsWorld, save state, network authority, ecosystem, or agent
behavior. GPU timestamp results use the same delayed policy.

Update rates, threading, and GPU ownership
-----------------------------------------

The render thread builds one immutable plan per view family/frame. Command
recording may fan out by compiled pass. Transfer/compute/graphics queues execute
only RenderGraph-compiled ownership. DeepWaterSpectralOcean owns persistent FFT
inputs/outputs; coast, interaction, effects, media, habitat, and agents own
their persistent resources; RenderGraph owns transients; this plan owns only
registrations/readback metadata and module-owned staging payloads. Actual
retirement callbacks are queued in FrameManager's single GpuRetirementQueue.

Lifecycle and dependencies
--------------------------

Register declarations after device/queue selection and before first frame.
Resize/quality/device recreation builds a complete new resource generation,
warms required initial state, then switches atomically; prior generations retire
by their maximum timeline. Device loss invalidates all GPU plans/readbacks while
CPU ocean simulation continues. See ..\rendering\03_render_graph.txt,
..\vulkan\19_command_scheduler.txt, ..\vulkan\20_frame_manager.txt,
..\vulkan\02_gpu_resource_manager.txt, 74_deep_water_spectral_ocean.txt,
78_ocean_surface_renderer.txt, and 79_underwater_media_renderer.txt.

Failure and error behavior
--------------------------

Errors include UndeclaredUse, ReadBeforeWrite, WriteAfterWrite,
MissingQueueTransfer, UnsupportedQueue, ResourceGenerationMismatch,
OriginGenerationMismatch, HistoryStillInFlight, ReadbackRingFull,
TimelineRegression, and DeviceLost. Invalid plans do not execute. Optional
producers fall back by the ordered quality policy; required surface inputs hold
the last completed coherent generation or skip the dependent pass. Readback
overflow drops the lowest-priority diagnostic request and never stalls.

Deterministic and testing strategy
----------------------------------

Graph compilation tests cover every producer/consumer edge, FFT stage barriers,
compute-to-fragment sampling, compute indirect-write to draw-indirect-read,
transfer-to-compute, queue-family release/acquire, history reuse, resize/origin
invalidation, and retirement with three frames in flight. Run plans on unified
and separate queue families. Vulkan validation must report zero hazards. Fault
tests delay queues, exhaust readback slots, recreate swapchain/device, and prove
CPU authoritative hashes remain identical with GPU disabled or delayed.

Performance and scalability
---------------------------

Transient aliasing is permitted only for non-overlapping compiled lifetimes.
Batch barriers at pass boundaries without broad ALL_COMMANDS/MEMORY uses.
Prefer async overlap for FFT/media only when timestamp evidence shows gain;
avoid starving graphics. Readback defaults below 64 KiB/s and two frames of
latency. Track queue occupancy, overlap, barrier count, ownership transfers,
timeline lag, transient/persistent bytes, history resets, readback age/bytes,
and per-pass p50/p95/p99.

Integration points and acceptance
---------------------------------

Every GPU-producing ocean module registers here and references conventions in
87_ocean_conventions_invariants.txt. RenderGraph remains the sole scheduler.
Acceptance requires graph-lint success, zero validation hazards for 10,000
stress frames, no host/queue idle wait, correct output on unified/split queues,
readback never observed by authoritative modules, and safe retirement under
resize, origin shift, quality transition, and device loss.

Engine-wide integration contract
--------------------------------

Normative ocean GPU specialization of RenderGraph, not a second scheduler or
deletion queue. GpuTimelinePoint is always QueueId-qualified and retirement
uses GpuCompletionSet/CompletedGpuTimelines. All errors/results and device-loss
containment follow ..\ERROR_RESULT_POLICY.txt; ownership follows
..\OWNERSHIP_LIFETIME_SHUTDOWN.txt and ..\vulkan\INDEX.txt.
