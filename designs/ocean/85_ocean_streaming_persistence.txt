OCEAN STREAMING AND PERSISTENCE CLASS DESIGN
============================================

Class
-----

    OceanStreamingService

Purpose
-------

Act as the ocean participant in WorldStreamingManager: coordinate ocean content
inside admitted WorldCellLease plans, large-world precision, asynchronous
prepare/activation/eviction, and versioned save fragments across ocean modules.
It does not own global observers, admission, or save files.

Public API
----------

    void ApplyWorldCellPlan(const WorldCellPlan&);
    Result<void, OceanPersistenceError> AttachLease(WorldCellLease);
    void UpdateOceanContentPriorities(OceanTick);
    OceanCellRequest Request(OceanCellKey, OceanContentMask, Priority);
    void Cancel(OceanCellRequest);
    OceanCellStatus Status(OceanCellKey) const;
    void CommitAtTickBoundary(OceanTick);
    Result<void, OceanPersistenceError> SaveDirtyCells(SaveTransaction&);
    Result<void, OceanPersistenceError> Restore(const OceanSaveManifest&);
    OceanStreamingStatistics Statistics() const;

Key data structures
-------------------

OceanCellKey is signed integer X/Y plus vertical layer, LOD, and world datum;
positions within a cell remain double precision. OceanCellRecord stores desired/
resident content masks, per-module state machine/generation, dependency tokens,
reader count, dirty/version flags, memory costs, priority, and failure context.
OceanSaveManifest stores OceanEpoch, schema/module versions, catalog hashes,
global named-animal records, tide/weather overrides, and sorted cell deltas.
CellDelta contains coastal residual state, persistent wakes, habitat patches,
ecosystem cohorts/reservations, acoustic overrides, and checksums.

Algorithms and models
---------------------

WorldStreamingManager observers generate the global required/preload/retention
plan and leases. This service refines each admitted lease into nested ocean
content priorities for authoritative physics, coastal boundaries, visual
spectra/effects, ecology agents/statistics, habitat, and acoustics without
exceeding the lease budget. It reports required lead/radius/cost back to the
global planner; it cannot admit a world cell independently.
Build a dependency DAG per cell: bathymetry/forcing before coast, coast/habitat
before ecosystem, ecosystem before agents. Jobs may load out of order but
activation is a transaction at a fixed-tick boundary after all required
generations match.

Ocean simulation never stores a single rebased float world position. CPU state
uses cell key plus double local coordinate; global analytic wave/tide phase uses
integer cell offset and range-reduced double dot products. GPU packets use
high/low split relative to WorldCoordinateSystem origin plus origin generation.
Origin rebase publishes a new transform; resident cell data and physical phases
do not move. In-flight packets retain their transform generation.

Cell/local canonicalization follows file 87 at every API boundary. Phase
evaluation multiplies signed integer cell offset using compensated/range-reduced
double arithmetic before adding local k dot x. GPU high/low split is generated
once per packet, and reconstruction error is checked against the physics-band
position tolerance. Rebasing never rewrites saved cells, coastal grids,
ecosystem locations, or spectrum H0; it invalidates only render transforms and
histories carrying the old OriginGeneration.

Eviction stops new readers, demotes agents, seals/exports conservative boundary
flux, settles promotion/source ledgers, serializes dirty deltas, then retires
CPU/GPU generations. Distant time is advanced statistically from saved tick
with bounded analytic/coarse catch-up, not thousands of hidden frame steps.

For networked sessions the authority replicates OceanEpoch, tick, forcing
transitions, interactor/source inputs, persistent cell deltas, and periodic
authoritative query/coastal/ecosystem checksums. Clients reconstruct deep waves
and visual effects locally from versioned seeds and request a compact coastal
state correction on checksum drift. GPU displacement, foam textures, particles,
and per-fish render instances are never replicated. Join-in-progress receives a
manifest plus prioritized safety-radius cells before enabling vessel control.

Save data includes only authoritative epoch/ticks, deterministic RNG counters,
analytic transition progress, conservative coastal/wake residuals and ledgers,
ecosystem cohorts/reservations/transit routes, persistent identities, queued
physical/acoustic events, and module versions. Serialization sorts keys/IDs,
uses explicit endian/float encoding, rejects NaN, and hashes each page plus the
manifest. GPU histories, FFT outputs reconstructible from H0, visual particles,
audio voice phase, caches, and quality tier are excluded. Restore publishes
nothing until page hashes, cross-page ledgers, dependency generations, and epoch
are coherent; interrupted save retains the prior atomic manifest.

Update rates, threading, and GPU ownership
-----------------------------------------

Priority selection runs at 5-10 Hz and on observer jumps. I/O/decompression/
schema migration run on jobs; simulation activation/eviction commits at tick
boundaries; GPU upload/destruction is registered on render/transfer queues and
retires after its GpuCompletionSet. StreamingService owns records/tokens, not
module resources.
No blocking I/O occurs on simulation, render, physics, or audio threads.

Lifecycle and dependencies
--------------------------

Create after WorldStreamingManager, WorldCoordinateSystem, VFS, AssetManager,
JobSystem, and OceanEpoch. Register as world-cell participant and save-state
provider. Restore manifest bundle before activating cells.
Module registration declares dependencies, cost estimator, load/activate/
deactivate/serialize callbacks, and schema version. Shutdown cancels requests,
settles cells, commits save transaction, and waits only on owned jobs/timelines.

Failure and error behavior
--------------------------

Errors include DependencyCycle, DatumMismatch, EpochMismatch, ChecksumFailure,
SchemaUnsupported, ActivationRollback, SaveTransactionFailed, BudgetDeadlock,
ReaderLeak, OriginGenerationMismatch, NonCanonicalCoordinate,
LedgerRestoreMismatch, and DeterministicReplayMismatch. Activation is all-or-nothing for the
required content mask. Corrupt optional visual data regenerates from seed;
corrupt authoritative deltas are quarantined and reported, never silently reset
over the only save. Budget deadlock evicts optional/far content by stable policy
or blocks new activation without unloading a cell still referenced.

Deterministic and testing strategy
----------------------------------

Canonical keys/priorities/tie breaks and tick-boundary commits make residency
decisions replayable for a recorded observer stream. Tests cover negative/huge
cells, multi-observer union, high-speed travel, preload hysteresis, cancellation,
dependency rollback, reader-delayed eviction, origin shift with in-flight GPU
frames, spectral phase across cell seams, deep/coastal boundary residency,
agent demotion ledger, interrupted atomic save, checksum/schema migration,
unloaded-time catch-up, device loss, and byte/tolerance save continuation.
Network tests add late join, packet reorder/loss, seed/version mismatch,
checksum correction, and identical authoritative vessel samples after recovery.
Replay tests save on every phase boundary, reload with different worker/render
cadence and origin sequence, and require identical supported-CPU authoritative
hashes, ledgers, persistent identities, and queued-event delivery ticks.

Performance and scalability
---------------------------

Use compact records, sparse key maps, batched sorted I/O, shared immutable base
assets, compressed deltas, incremental checksums, cost-aware admission, and
separate CPU/GPU/I/O budgets. Residency policy can drop visual effects, habitat
instances, agent detail, coastal visual refinement, then distant statistics;
authoritative vessel/coast dependencies are pinned within safety radius.
Profile requests, latency stages, churn, bytes, module costs, save backlog,
reader stalls, origin generations, and prediction accuracy.

Integration points
------------------

WorldStreamingManager supplies world observers and shared cell scheduling.
WorldCoordinateSystem supplies render origin generations. Every ocean module
registers content lifecycle callbacks. SaveSystem supplies atomic transactions.
Renderer/FrameManager supply retirement timelines. Diagnostics exposes the
dependency graph, residency rings, budgets, state transitions, errors, and dirty
cells without mutating them.

Engine-wide integration contract
--------------------------------

Normative ocean participant/record coordinator, not a second global streaming
or persistence owner. WorldStreamingManager owns observers/admission/leases;
modules own resources; SaveSystem owns atomic files/restore bundle; this service
owns ocean record state, dependency transaction, and serialized ocean fragments.
GPU work retires through FrameManager's central GpuCompletionSet queue. See
..\world\10_world_streaming_manager.txt,
..\OWNERSHIP_LIFETIME_SHUTDOWN.txt, and ..\FRAME_THREADING_MODEL.txt.
