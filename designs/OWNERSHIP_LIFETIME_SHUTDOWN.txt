ENGINE OWNERSHIP, LIFETIME, AND SHUTDOWN ORDER
==============================================

Status
------

Normative ownership graph. "Depends on" in class documents is not ownership
unless this file says so. ApplicationHost is the composition root; subsystems
do not construct or destroy peer services.

Authoritative owners
--------------------

ApplicationHost:
    PlatformRuntime/Window, configuration, diagnostics, clocks, jobs, VFS,
    asset services, world/simulation services, presentation services, Renderer,
    and AudioSystem. Ownership uses values/unique ownership in reverse declared
    destruction order.

VulkanRuntime:
    vk::raii context, instance, debug messenger adapter, surface, selected
    physical device, logical device, and queue handles. It does not own frame,
    command, resource, descriptor, graph, or swapchain policy.

MemoryManager:
    Allocation backend and allocation objects only. It never owns a deferred
    deletion queue or guesses GPU completion.

CommandScheduler:
    Queue submission serialization, command pools, timeline semaphores, and
    monotonic per-queue values. It is the only timeline-value allocator.

GpuResourceManager:
    Generation-checked buffer/image/view/sampler records, allocation RAII,
    upload staging, explicit compiled state, and last-use GpuCompletionSet.
    Release invalidates the handle immediately, then transfers an RAII payload
    to the FrameManager-owned GpuRetirementQueue.

FrameManager:
    Bounded FrameSlot records and the one GpuRetirementQueue for the renderer.
    It polls CommandScheduler; it does not allocate timeline values. Retirement
    callbacks run only after every point in their GpuCompletionSet completes.

SwapchainManager:
    Swapchain generations, borrowed swapchain images, owned views, and acquire/
    present binary semaphores. Old generations retire through
    GpuRetirementQueue; no global idle is required for resize.

DescriptorAllocator:
    Descriptor pools/layout-cache records/set generations. Transient sets are
    bound to a caller-supplied FrameSlotId and expire only after that slot's
    GpuCompletionSet. It does not own frames or shaders.

RenderGraph:
    Per-frame declarations, compiled pass DAG, transient resource lifetimes and
    synchronization plan. It does not own persistent resources or queues.

AssetRegistry:
    Immutable mapping from AssetId to cooked record/dependencies and registry
    generation. AssetManager owns runtime load slots; Mesh/Texture/Material/
    Shader systems own their typed runtime/GPU generations. FileWatcherHotReload
    coordinates replacement but owns neither old nor new consumer resources.

EntityRegistry:
    EntityId lifetime and component storage. PhysicsWorld owns BodyId/backend
    bodies; CollisionSystem owns shared shape records; each gameplay system owns
    only its registered runtime records. PersistentEntityId mapping belongs to
    save/network identity services, not EntityId.

WorldStreamingManager:
    Global observers, desired world-cell plan, admission/budget decisions, and
    WorldCellLease transactions. Terrain, navigation, ocean, gameplay, and audio
    participants own their resources and report readiness/cost. OceanStreamingService
    is the ocean participant/coordinator, not a second global residency owner.

OceanDomain and modules:
    OceanDomain owns epoch and publication orchestration. Each producing module
    owns the state named in ocean\72_ocean_domain_coordinator.txt. OceanQueryService
    owns composition/scratch only. Renderers own visual resources only.

SaveSystem:
    Save transaction/files/migrations only. Registered providers own live state
    and immutable save snapshots. A load builds an isolated WorldRestoreBundle;
    ApplicationHost commits it at a boundary after all providers validate.

AudioSystem and UISystem:
    Backend/voices and widget/presentation state respectively. They retain
    copied snapshots and issue commands/events; they never own gameplay objects.

Borrowing and asynchronous work
-------------------------------

A borrow cannot outlive its call unless represented by Snapshot<T>,
SharedAsset<T>, WorldCellLease, RegistrationToken, or another named RAII type.
Callbacks return RegistrationToken and are invoked outside owner locks. Jobs
capture immutable snapshots and cancellation tokens, never component references
or stack spans. C callbacks receive stable context whose owner unregisters and
drains callbacks before context destruction.

Construction order
------------------

1. DebugDiagnostics core, ConfigurationSettings, PlatformRuntime/Window.
2. SimulationClock, JobSystem, VirtualFileSystem, SchemaSerialization.
3. AssetRegistry and AssetManager; offline cooker/hot reload only if enabled.
4. WorldCoordinateSystem, EntityRegistry, command bus, collision/physics,
   time/weather, world streaming and terrain/navigation participants.
5. Sailing/gameplay and ocean contracts/domain/modules; ecosystem/audio control.
6. VulkanRuntime: PhysicalDeviceSelector is a stateless bootstrap helper.
7. CommandScheduler, MemoryManager, GpuRetirementQueue/FrameManager,
   GpuResourceManager, DescriptorAllocator, SwapchainManager, RenderGraph.
8. Typed render resources/systems and Renderer facade.
9. UISystem, GameHUD, menus, DevelopmentUI, final audio device start.

All constructors are transactional. A service becomes discoverable only after
full initialization; rollback destroys only objects already constructed.

Shutdown order
--------------

1. ApplicationHost closes command/input ingress and publishes ShuttingDown.
2. Stop file watching, network ingress, new asset/world/ocean requests, and
   save initiation. Audio callback switches to a bounded fade/silence frame.
3. Stop gameplay ticks after one boundary; publish terminal render/audio/save
   snapshots. Reject new registrations and handles.
4. WorldStreamingManager asks participants to demote agents, settle ledgers,
   flush required dirty snapshots, and release leases. Save transaction either
   atomically commits or reports failure without partial replacement.
5. Cancel/join subsystem and I/O jobs while JobSystem still exists. No callback
   may target a destroyed owner.
6. Destroy UI/debug/render pass providers; Renderer stops building frames.
7. FrameManager drains submitted GpuCompletionSets, then GpuRetirementQueue.
   Device loss uses best-effort host cleanup and does not wait forever.
8. Destroy typed render systems, swapchain, descriptors, GPU resources, memory,
   frame/scheduler objects, then VulkanRuntime/device/instance/surface.
9. Stop audio device/callback, destroy backend, then simulation/world/assets/VFS.
10. Join JobSystem, destroy Window/PlatformRuntime, flush diagnostics last.

`vkDeviceWaitIdle` is permitted only in explicit final shutdown or recovery
when bounded timeline draining cannot proceed; never normal frame/resize/hot
reload. Shutdown is idempotent and handles partial construction.

Required lifetime tests
-----------------------

Construction failure at every step, release while GPU/in-flight readers exist,
stale handle reuse, resize/hot reload/device loss, streaming eviction with
pinned snapshots, save during unload, callback unregistration races, worker
cancellation, and shutdown from every phase. Leak checks include CPU owners,
Vulkan objects, descriptor/frame pools, cell leases, entity/body/shape mappings,
asset generations, audio voices, and registration tokens.
