SAVE SYSTEM CLASS DESIGN
========================

Class:

    SaveSystem

Purpose:

    Serialize versioned game state, validate loaded data, migrate older
    versions, and commit saves atomically without serializing runtime handles.

Public API:

    Result<SaveReceipt, SaveError> Save(const SaveRequest& request);
    Result<WorldRestoreBundle, SaveError> Load(const SaveSlot& slot);
    Result<SaveMetadata, SaveError> ReadMetadata(const SaveSlot& slot) const;
    Result<std::vector<SaveMetadata>, SaveError> ListSaves() const;
    void RegisterMigration(SaveVersion from, MigrationFunction migration);

Saved data:

    Format version.
    Build-compatible schema version.
    Timestamp and play time.
    Player/vessel state.
    Inventory and progression.
    Mission state.
    Time and weather snapshot.
    World-cell modifications.
    AssetId and PersistentEntityId; never EntityId or runtime handles.
    Deterministic seeds.

Save transaction:

    Capture an immutable snapshot at a safe simulation point.
    Serialize to a temporary file.
    Validate section sizes and checksums.
    Flush and close.
    Rotate existing save to backup.
    Atomically replace final save.

Load transaction:

    Read bounded header.
    Validate magic/version/declared sizes.
    Verify checksum.
    Parse into temporary structures.
    Run sequential migrations.
    Validate semantic values and asset IDs.
    Return an isolated WorldRestoreBundle only after the entire load succeeds.
    ApplicationHost validates every registered provider and commits the bundle
    at P3; SaveSystem never mutates a live world directly.

Rules:

    Never serialize pointers, Vulkan handles, file paths, or component memory
    dumps.
    Never partially apply a failed load.
    Keep user settings in a separate file.
    Enforce maximum section/decompressed sizes.
    Preserve backup after corruption.

Errors:

    SaveNotFound
    UnsupportedVersion
    CorruptData
    ChecksumMismatch
    MigrationFailed
    MissingAsset
    CommitFailed

Tests:

    Round trip representative state.
    Truncated/corrupt files.
    Oversized declared section.
    Migration chain.
    Failed load leaves current state unchanged.
    Atomic replacement and backup recovery.
    Deterministic state restored exactly.

Dependencies:

    VirtualFileSystem
    SchemaSerialization
    Registered SaveStateProvider interfaces

Canonical integration contract:

    Normative transaction service. Providers own live state and publish
    immutable P11 snapshots with schema, units, epoch, TickId, AssetId,
    PersistentEntityId, and deterministic seed state. Save work may serialize
    on I/O workers; snapshot capture and restore commit run on the simulation
    boundary. Provider registrations are RAII and frozen while a transaction is
    active. Missing required provider data fails the transaction; no default
    world is silently substituted.

    See ..\FRAME_THREADING_MODEL.txt,
    ..\OWNERSHIP_LIFETIME_SHUTDOWN.txt, ..\ERROR_RESULT_POLICY.txt,
    ..\assets\30_virtual_filesystem.txt, and 68_schema_serialization.txt.
