CONFIGURATION SETTINGS CLASS DESIGN
===================================

Class:

    ConfigurationSettings

Purpose:

    Load layered typed configuration, validate ranges, apply runtime-safe changes, and persist user settings atomically.

Public API:

    RegisterSchema(entries);
    Load(defaults,project,user,cli);
    Get<T>(key);
    Set<T>(key,value);
    Subscribe(key,callback);
    ApplyPending();
    SaveUser();
    Reset(category);

Internal state and components:

    - typed key/value store.
    - schema/defaults/ranges.
    - source provenance.
    - pending changes.
    - restart-required flags.
    - subscribers.
    - dirty state.

Lifecycle and ownership:

    service owns values; callers receive copies; subscription is RAII token; atomic save uses replace and backup

Error behavior:

    Get/Set/load/save return Result values for unknown key, type/range, parse,
    I/O, and transaction failures. ApplyPending publishes all validated values
    or none; subscriber failure is contained and reported after publication.

Threading and timing constraints:

    Set may originate on UI thread; ApplyPending runs at main-loop safe point; callbacks never run under settings lock

Dependencies:

    - VirtualFileSystem.
    - DebugDiagnostics.
    - GraphicsQualityManager consumes settings snapshots; no reverse ownership.

Tests:

    - layer precedence.
    - invalid type/range.
    - unknown key policy.
    - atomic save recovery.
    - callback ordering.
    - restart flag.
    - concurrent reads.

Implementation rules:

    - Keep implementation-only types out of public headers.
    - Use RAII and generational IDs; do not expose owning raw pointers.
    - Validate descriptions before allocating or mutating state.
    - Publish complete snapshots/generations rather than partially updated data.
    - Add diagnostics for failure context without making logging a dependency
      of correctness.

Canonical integration contract:

    Normative settings owner. User/project values are SI or explicitly
    dimensionless and carry schema version/provenance. UI may stage changes on
    the main thread; P13 publishes immutable settings generations. GPU/world
    rebuild owners consume a ReconfigurePlan and report Result without mutating
    settings recursively. Subscription tokens are RAII; callbacks execute
    outside locks.

    See ..\FRAME_THREADING_MODEL.txt, ..\ERROR_RESULT_POLICY.txt,
    ..\assets\30_virtual_filesystem.txt, and
    ..\rendering\56_graphics_quality.txt.
