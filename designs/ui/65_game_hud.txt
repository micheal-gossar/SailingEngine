GAME HUD CLASS DESIGN
=====================

Class:

    GameHUD

Purpose:

    Present sailing instruments, mission status, interaction prompts, inventory summaries, and damage indicators from snapshots.

Public API:

    BindPlayer(player);
    Update(HudSnapshot,RenderDeltaSeconds);
    SetLayout(layout);
    ShowPrompt(prompt);
    ClearPrompt(id);
    BuildWidgets();
    SetVisibility(mode);

Internal state and components:

    - smoothed compass/speed/wind values.
    - notification queue.
    - prompt priorities.
    - layout anchors.
    - accessibility presentation state.

Lifecycle and ownership:

    HUD owns presentation state/widgets only; snapshots and prompt payloads copied; no direct gameplay ownership

Error behavior:

    Invalid player/prompt/layout/snapshot generation and notification capacity
    return HudError/status. Missing values show an explicit unavailable state,
    not a plausible zero instrument reading.

Threading and timing constraints:

    main UI update; smoothing uses render delta but authoritative values remain unchanged; notifications bounded/coalesced

Dependencies:

    - UISystem.
    - HudSnapshot built from player/mission/inventory presentation snapshots.
    - AccessibilitySnapshot from MenuAccessibilitySystem.

Tests:

    - instrument mapping.
    - angle wrap smoothing.
    - prompt priority/expiry.
    - missing player.
    - resize/safe area.
    - notification overflow.

Implementation rules:

    - Keep implementation-only types out of public headers.
    - Use RAII and generational IDs; do not expose owning raw pointers.
    - Validate descriptions before allocating or mutating state.
    - Publish complete snapshots/generations rather than partially updated data.
    - Add diagnostics for failure context without making logging a dependency
      of correctness.

Canonical integration contract:

    Normative HUD presentation owner only. P12 PresentationModel copies sailing,
    mission, inventory, damage, prompt, and accessibility values with units and
    generations into HudSnapshot; GameHUD has no runtime ownership dependency
    on those systems. P13 smoothing uses render delta on copied values only and
    never feeds commands or authority. User actions route through UISystem/
    GameplayCommandBus.

    See ..\FRAME_THREADING_MODEL.txt, 36_ui_system.txt, and
    ..\sailing\INDEX.txt.
