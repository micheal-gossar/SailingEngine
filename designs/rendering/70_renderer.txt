RENDERER CLASS DESIGN
=====================

Class:

    Renderer

Purpose:

    Orchestrate per-frame view extraction, render graph construction, GPU submission, presentation, and recovery without owning gameplay.

Public API:

    Render(RenderWorldSnapshot,CameraView)->RenderResult;
    Resize(extent);
    SetQuality(settings);
    CaptureFrame(request);
    WaitIdle(ShutdownOrRecoveryToken);
    Statistics();
    HandleDeviceLost();

Internal state and components:

    - VulkanRuntime.
    - swapchain/frame/command managers.
    - render graph.
    - system pass providers.
    - per-frame view constants.
    - recovery state.

Lifecycle and ownership:

    Renderer owns Vulkan-facing services/pass registrations in the exact order
    defined by the root ownership document; it consumes immutable snapshots.
    Shutdown stops pass providers, drains frame completion/retirement, and
    destroys VulkanRuntime last.

Error behavior:

    Render returns RenderResult with Rendered/Skipped/Suspended/OutOfDate/
    Degraded/DeviceLost status plus Error where applicable. It is the Vulkan
    exception/device-loss containment boundary; failed frame build submits
    nothing partial.

Threading and timing constraints:

    render thread/main thread per platform; one Render at a time; minimized extent skips acquire; GPU work never reads mutable simulation

Dependencies:

    - VulkanRuntime.
    - FrameManager.
    - SwapchainManager.
    - RenderGraph.
    - GpuResourceManager.
    - Registered IRenderPassProvider interfaces.

Tests:

    - clear/present.
    - resize/minimize.
    - frame overlap.
    - snapshot lifetime.
    - quality rebuild rollback.
    - acquire/present status.
    - device-lost exit/recovery.

Implementation rules:

    - Keep implementation-only types out of public headers.
    - Use RAII and generational IDs; do not expose owning raw pointers.
    - Validate descriptions before allocating or mutating state.
    - Publish complete snapshots/generations rather than partially updated data.
    - Add diagnostics for failure context without making logging a dependency
      of correctness.

Canonical integration contract:

    Normative rendering facade/composition owner. P14 extracts immutable
    CameraView/RenderWorldSnapshot; P15 acquires a frame, builds/compiles one
    RenderGraph, submits through CommandScheduler, and presents; P16 polls and
    retires. Normal frame/resize/reload never calls queue/device idle. Renderer
    does not own gameplay and cannot expose GPU/readback state to simulation.
    Pass providers retain required generations through returned completion.

    See ..\FRAME_THREADING_MODEL.txt,
    ..\OWNERSHIP_LIFETIME_SHUTDOWN.txt, ..\vulkan\INDEX.txt, and INDEX.txt.
