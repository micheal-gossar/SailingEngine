CLOUD SYSTEM CLASS DESIGN
=========================

Class:

    CloudSystem

Purpose:

    Render scalable volumetric or impostor clouds driven by weather while producing lighting and shadow inputs.

Public API:

    SetQuality(level);
    Update(weather,time,view);
    AddPasses(graph);
    CloudShadowMap() const;
    CoverageAt(worldPos) const;
    ResetHistory();

Internal state and components:

    - weather volume/noise textures.
    - temporal history.
    - reprojection matrices.
    - cloud shadow map.
    - quality parameters.
    - history validity.

Lifecycle and ownership:

    owns GPU volumes/history; resize/quality replacement deferred; gameplay coverage comes from WeatherSystem, not rendered samples

Error behavior:

    Invalid quality/input generation, history, capability, allocation, and GPU
    failures return CloudError. Named impostor/no-compute fallback is tagged in
    the frame; gameplay coverage always remains WeatherSnapshot data.

Threading and timing constraints:

    render-thread update; async compute optional; camera cuts/origin shifts invalidate history; bounded temporal feedback

Dependencies:

    - RenderGraph.
    - WeatherSystem.
    - SkyAtmosphereSystem.
    - TextureSystem.
    - CameraSystem.

Tests:

    - history reset.
    - quality scaling.
    - camera cut.
    - wind advection.
    - missing compute fallback.
    - shadow output.

Implementation rules:

    - Keep implementation-only types out of public headers.
    - Use RAII and generational IDs; do not expose owning raw pointers.
    - Validate descriptions before allocating or mutating state.
    - Publish complete snapshots/generations rather than partially updated data.
    - Add diagnostics for failure context without making logging a dependency
      of correctness.

Canonical integration contract:

    Normative visual pass provider. P12 copies WeatherSnapshot and SkyLighting/
    Camera values; P14-P16 own all cloud histories and rendering. CoverageAt is
    diagnostic/visual only and must be renamed VisualCoverageAt in implementation;
    gameplay samples WeatherSystem. Histories carry view, weather, origin,
    extent, algorithm, and resource generations and reject mismatches.

    See ..\FRAME_THREADING_MODEL.txt, 27_sky_atmosphere.txt, and INDEX.txt.
