GRAPHICS QUALITY CLASS DESIGN
=============================

Class:

    GraphicsQualityManager

Purpose:

    Map user quality settings and measured capability to coherent render budgets and safe runtime reconfiguration.

Public API:

    DetectCapabilities(runtime);
    ApplyPreset(name);
    Set(option,value);
    EffectiveSettings();
    BuildReconfigurePlan(old,new);
    ConfirmApplied(plan);
    Recommend(targetFps);

Internal state and components:

    - option schema.
    - presets.
    - hardware limits.
    - requested/effective values.
    - dependency rules.
    - restart/recreate flags.
    - measured tier.

Lifecycle and ownership:

    manager owns settings snapshot; reconfigure plan value object consumed at frame boundary; rollback retains previous snapshot

Error behavior:

    Invalid option/preset, unsatisfied capability/budget, failed reconfiguration,
    and stale plan return QualityError. Failed application retains the old
    effective snapshot and records requested versus effective values.

Threading and timing constraints:

    updates main thread; GPU resource recreation staged at frame boundary; no setting mutates resources directly

Dependencies:

    - ConfigurationSettings.
    - VulkanRuntime.
    - Renderer capability/metrics snapshots.
    - Render systems consume QualityDecision; no reverse ownership.

Tests:

    - preset mapping.
    - capability clamp.
    - dependent options.
    - rollback failed recreation.
    - serialization.
    - recommendation hysteresis.

Implementation rules:

    - Keep implementation-only types out of public headers.
    - Use RAII and generational IDs; do not expose owning raw pointers.
    - Validate descriptions before allocating or mutating state.
    - Publish complete snapshots/generations rather than partially updated data.
    - Add diagnostics for failure context without making logging a dependency
      of correctness.

Canonical integration contract:

    Normative policy owner, not a resource owner. It produces a versioned
    QualityDecision/ReconfigurePlan at P13; modules independently prepare
    replacements and Renderer atomically commits only when required results
    succeed. Hysteresis prevents oscillation. Visual quality never changes fixed
    simulation, deterministic seeds, authoritative ocean band/cells, save/
    network state, units, or physics/AI update policy.

    See ..\core\31_configuration_settings.txt,
    ..\INTEGRATION_ACCEPTANCE_MATRIX.txt, and ..\ocean\86_ocean_validation_quality.txt.
