GAMEPLAY COMMAND BUS CLASS DESIGN
=================================

Class:

    GameplayCommandBus

Purpose:

    Validate, sequence, queue, and dispatch all state-changing gameplay commands at deterministic tick boundaries.

Public API:

    RegisterHandler(type,handler);
    Enqueue(command,source);
    DrainForTick(tick);
    Dispatch(batch,world);
    Reject(reason);
    Record(batch);
    Replay(log);

Internal state and components:

    - bounded MPSC ingress.
    - command envelope tick/source/sequence/type/payload.
    - validators.
    - handler table.
    - replay journal.

Lifecycle and ownership:

    bus owns queued payload values; handler registrations are RAII and fixed while world runs; replay log versioned

Error behavior:

    Invalid schema/source/tick/target, stale ID, late/future policy, duplicate
    sequence, capacity, and handler failure return CommandError/rejection
    records. Handler exceptions are contained at dispatch and abort remaining
    transaction work according to command policy; same-tick recursion fails.

Threading and timing constraints:

    producers may enqueue concurrently; single simulation thread assigns canonical order and dispatches; no handler recursively dispatches same tick

Dependencies:

    - TickId value from SimulationClock.
    - EntityRegistry.
    - SchemaSerialization.
    - Network/UI/input/debug/AI are producers; replay/save are journal consumers.

Tests:

    - multi-producer ordering.
    - invalid/stale target.
    - queue overflow.
    - replay equality.
    - handler exception boundary.
    - future/late tick policy.

Implementation rules:

    - Keep implementation-only types out of public headers.
    - Use RAII and generational IDs; do not expose owning raw pointers.
    - Validate descriptions before allocating or mutating state.
    - Publish complete snapshots/generations rather than partially updated data.
    - Add diagnostics for failure context without making logging a dependency
      of correctness.

Canonical integration contract:

    Normative state-change ingress and queued-value owner. Producers may enqueue
    bounded immutable envelopes concurrently. The P2 simulation thread validates
    schema/EntityId generation, assigns canonical ordering, and dispatches one
    batch. The bus has no producer or SaveSystem ownership dependency, breaking
    network/save cycles. Handlers are registered by RAII before world activation,
    execute outside ingress locks, and may enqueue only a future-tick command.

    See ..\FRAME_THREADING_MODEL.txt, ..\ERROR_RESULT_POLICY.txt, and INDEX.txt.
