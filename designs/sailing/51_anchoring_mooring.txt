ANCHORING MOORING CLASS DESIGN
==============================

Class:

    AnchoringMooringSystem

Purpose:

    Model anchor deployment, seabed hold, rode tension, and breakable mooring constraints.

Public API:

    DeployAnchor(vessel,request);
    RaiseAnchor(vessel);
    AttachMooring(vessel,point,rope);
    Detach(id);
    Step(TickId,FixedDeltaSeconds);
    State(vessel);
    DrainEvents();

Internal state and components:

    - anchor state machine.
    - seabed hit/hold point.
    - rode length.
    - rope constraints.
    - winch speed.
    - tension/break thresholds.

Lifecycle and ownership:

    system owns constraint IDs and removes them before vessel/body destruction; world points use double precision

Error behavior:

    Invalid/stale vessel/constraint, unavailable seabed, invalid rope units,
    capacity, and physics-query failure return MooringError. Missing/unknown
    bathymetry is not interpreted as seabed.

Threading and timing constraints:

    fixed simulation step; raycasts occur at defined phase; attach/detach commands queued to boundary

Dependencies:

    - VesselStepContext and PhysicsWorld command/query interfaces.
    - Terrain/Bathymetry immutable query snapshot.
    - Collision ShapeHandle values.

Tests:

    - deploy no seabed.
    - holding radius.
    - winch.
    - tension break.
    - body destruction.
    - origin shift.
    - save/restore deployed state.

Implementation rules:

    - Keep implementation-only types out of public headers.
    - Use RAII and generational IDs; do not expose owning raw pointers.
    - Validate descriptions before allocating or mutating state.
    - Publish complete snapshots/generations rather than partially updated data.
    - Add diagnostics for failure context without making logging a dependency
      of correctness.

Canonical integration contract:

    Normative constraint-state owner. Deploy/attach/detach are GameplayCommands
    committed at P7 boundaries. Ray/query work uses generation-tagged
    WorldPosition and metres/newtons; returned BodyId/ShapeHandle are retained,
    not raw pointers. Constraint removal precedes BodyId/vessel destruction.
    Streaming pins the seabed generation for active anchors or explicitly
    transitions to Unavailable according to policy.

    See ..\CANONICAL_CONVENTIONS.txt, ..\world\INDEX.txt, and INDEX.txt.
