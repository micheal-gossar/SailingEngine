ASSET REGISTRY CLASS DESIGN
===========================

Class:

    AssetRegistry

Purpose:

    Map stable asset IDs to cooked artifacts, types, dependencies, versions, and source provenance.

Public API:

    LoadManifest(path)->Result<RegistryGeneration,RegistryError>;
    Resolve(RegistryGeneration,AssetId,type)->Result<AssetRecord,RegistryError>;
    FindByPath(RegistryGeneration,VirtualPath)->Result<AssetId,RegistryError>;
    Dependencies(RegistryGeneration,AssetId)->Result<span<const AssetId>,RegistryError>;
    Dependents(RegistryGeneration,AssetId)->Result<span<const AssetId>,RegistryError>;
    PrepareManifestDelta(delta)->Result<RegistryGeneration,RegistryError>;
    Validate(RegistryGeneration)->Result<void,RegistryError>;

Internal state and components:

    - ID-record maps.
    - path index.
    - dependency/reverse dependency graph.
    - content hashes.
    - artifact variants.
    - registry generation.

Lifecycle and ownership:

    Registry owns immutable record blocks/generations. AssetManager retains a
    RegistryGeneration during each load. Prepared delta publication is atomic;
    old blocks live until readers release them.

Error behavior:

    Corrupt/versioned manifest, duplicate ID/path, type mismatch, missing
    artifact/dependency, hash mismatch, or dependency cycle returns
    RegistryError. No partial generation is published.

Threading and timing constraints:

    manifest loading/cooking off-thread; validated immutable registry atomically published; lookups thread-safe

Dependencies:

    - VirtualFileSystem.
    - SchemaSerialization.
    - AssetCooker produces manifests offline; AssetManager consumes registry
      snapshots at runtime. Neither is owned by Registry.

Tests:

    - duplicate ID/path.
    - type mismatch.
    - missing dependency.
    - cycle policy.
    - delta while loading.
    - stable ID.
    - corrupt manifest.

Implementation rules:

    - Keep implementation-only types out of public headers.
    - Use RAII and generational IDs; do not expose owning raw pointers.
    - Validate descriptions before allocating or mutating state.
    - Publish complete snapshots/generations rather than partially updated data.
    - Add diagnostics for failure context without making logging a dependency
      of correctness.

Canonical integration contract:

    Normative AssetId authority. AssetId is stable logical identity and content
    hash identifies artifact revision; neither is a runtime handle. Records
    contain type, cooked VirtualPath, content/schema hashes, dependency AssetIds,
    variants, and provenance, but never runtime state/reference counts/GPU
    handles. Manifest loading may run on workers; validated generation
    publication occurs at P3/P13.

    See ..\CANONICAL_CONVENTIONS.txt, 05_asset_manager.txt,
    44_asset_cooker.txt, and INDEX.txt.
