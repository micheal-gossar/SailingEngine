MODEL IMPORTER CLASS DESIGN
===========================

Class:

    ModelImporter

Purpose:

    Import model sources into validated engine meshes, skeletons, animations, materials, and dependency records.

Public API:

    Import(path,options)->Result<ImportedScene,ImportError>;
    Probe(path)->Result<ImportFormat,ImportError>;
    Validate(scene)->Result<void,ImportError>;
    Flatten(scene,policy)->Result<ImportedScene,ImportError>;
    Dependencies(scene)->vector<SourceDependency>;

Internal state and components:

    - source-node graph.
    - coordinate/unit conversion.
    - mesh primitives.
    - skin/bones.
    - animations.
    - material references.
    - warning list.

Lifecycle and ownership:

    import result owns CPU data; source library objects never escape; runtime assets only created by cooker after validation

Error behavior:

    Unsupported/corrupt/unbounded source, ambiguous units/axes, invalid
    topology/skin/animation, missing required dependency, and backend failure
    return ImportError. Third-party C callbacks are `noexcept`; backend
    exceptions are caught at Import.

Threading and timing constraints:

    offline/job execution only; importer instance thread-confined unless backend documented safe; deterministic traversal/order

Dependencies:

    - VirtualFileSystem.
    - Cooked Mesh/Animation/Material format schemas only.

Tests:

    - axis/unit conversion.
    - triangulation.
    - bad indices.
    - bone weights normalization.
    - duplicate names.
    - missing textures.
    - deterministic ordering.

Implementation rules:

    - Keep implementation-only types out of public headers.
    - Use RAII and generational IDs; do not expose owning raw pointers.
    - Validate descriptions before allocating or mutating state.
    - Publish complete snapshots/generations rather than partially updated data.
    - Add diagnostics for failure context without making logging a dependency
      of correctness.

Canonical integration contract:

    Normative offline IAssetProcessor implementation. It has no AssetCooker or
    runtime system ownership dependency; AssetCooker invokes it through an
    interface. Source coordinates/units convert once into +X east/+Y north/+Z
    up SI local asset space, with transform parity/tangent/animation tests.
    ImportedScene owns CPU values and AssetId dependencies only.

    See ..\CANONICAL_CONVENTIONS.txt, 44_asset_cooker.txt, and INDEX.txt.
