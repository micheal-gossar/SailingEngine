ASSET MANAGER CLASS DESIGN
==========================

Class:

    AssetManager

Purpose:

    Resolve AssetId through an immutable AssetRegistry generation, load cooked
    files asynchronously, ask the registered typed factory to create a runtime
    generation, deduplicate requests, and report explicit failures. It does not
    duplicate registry metadata or own typed Mesh/Texture/Material/Shader data.

Public API:

    template<typename Asset>
    Result<AssetHandle<Asset>, AssetError> Request(AssetId id);

    template<typename Asset>
    AssetState State(AssetHandle<Asset> handle) const;

    template<typename Asset>
    Result<SharedAsset<const Asset>, AssetError> Get(
        AssetHandle<Asset> handle) const;

    void Update();
    void Release(UntypedAssetHandle handle);

States:

    Unloaded
    Queued
    Loading
    Uploading
    Ready
    Failed

Runtime load slot:

AssetId and retained AssetRegistry generation.
Expected type and typed-factory ID.
Registry record reference (artifact path/hash/dependencies).
Current state and readiness publication generation.
Generation.
Reference count.
Failure information.

Pipeline:

    Resolve ID.
    Return existing in-flight/ready request if present.
    Read bytes on I/O worker.
    Validate header/version/size.
    Decode/decompress on worker.
    Queue GPU upload if required.
    Publish ready asset atomically.

Supported initial assets:

    Mesh
    Texture
    Material
    Shader
    VesselDefinition
    WorldCell
    AudioClip

Rules:

    Missing assets become Failed, not empty Ready assets.
    Get returns AssetNotReady or AssetLoadError unless state is Ready.
    Fallback assets are explicit policy choices.
    GPU destruction waits for in-flight frames.
    Dependencies are acquired before the parent becomes Ready.
    Dependency cycles are rejected by the cooker and checked in debug builds.

Errors:

    UnknownAsset
    TypeMismatch
    UnsupportedVersion
    CorruptAsset
    DependencyFailed
    UploadFailed

Tests:

    Deduplicate concurrent requests.
    Load valid asset.
    Reject corrupt/truncated file.
    Propagate dependency failure.
    Reject stale handle.
    Release during loading safely.
    Verify GPU asset deferred deletion.

Dependencies:

    VirtualFileSystem
    AssetRegistry
    JobSystem
    Registered typed AssetFactory interfaces
    DebugDiagnostics

Canonical integration contract:

    Normative runtime-load coordinator. AssetId is stable/serializable; every
    AssetHandle<T> is process-local index/generation. Registry records are
    immutable snapshots. I/O/decode runs on jobs, simulation publication is P3,
    and GPU-backed typed factories publish at P13 after upload completion.
    Release invalidates only the runtime slot; typed owners retire GPU payloads
    through GpuCompletionSet. Hot reload prepares a new generation and swaps
    atomically; a failed reload retains the last valid generation with Error.

    See ..\CANONICAL_CONVENTIONS.txt, ..\FRAME_THREADING_MODEL.txt,
    69_asset_registry.txt, and INDEX.txt.
