CANONICAL ENGINE CONVENTIONS, TYPES, AND UNITS
==============================================

Status
------

Normative for every design below this directory. Public API fragments in older
class designs are conceptual unless they already use these types. Implemented
interfaces must follow this document and ERROR_RESULT_POLICY.txt. Domain
documents may add constraints but may not redefine a canonical type.

Names and identifiers
---------------------

Class and service names use the exact names in ARCHITECTURE_INDEX.txt. In
particular: GpuResourceManager, VirtualFileSystem, ConfigurationSettings,
PlayerSailingController, SailAerodynamicsSystem, HydrodynamicsSystem,
RudderSteeringSystem, RenderInterpolationSystem, and OceanDomain.

    EntityId               { uint32 index; uint32 generation; }
    Handle<Tag>             { uint32 index; uint32 generation; }
    AssetHandle<T>          a typed Handle whose slot is owned by AssetManager
    AssetId                 stable 128-bit logical cooked-asset identifier
    PersistentEntityId      stable 128-bit save/network identity
    TickId                  uint64 authoritative fixed-tick index
    RenderFrameId           uint64 presentation-frame index
    FrameSlotId             bounded reusable CPU frame slot
    OriginGeneration        generation of the render-relative origin
    GpuTimelinePoint        { QueueId queue; uint64 value; }
    GpuCompletionSet        one required GpuTimelinePoint per participating queue

EntityId and all Handle<Tag> values are process-local, generation checked, and
never serialized. No two handle domains are implicitly convertible. AssetId
and PersistentEntityId are serialized, but resolution can fail explicitly.
Zero/null values have a documented invalid meaning and are never silently
resolved to a default object.

Coordinates and units
---------------------

World space is right-handed: +X east, +Y north, +Z up. Angles are radians,
positive counter-clockwise from +X when viewed from +Z. Vectors describe
"toward" motion; imported meteorological "from" directions convert once at
ingestion.

Authoritative persistent positions use:

    WorldPosition { WorldCellKey cell; dvec3 localMeters; }

X/Y local coordinates are canonicalized to [0, worldCellSizeM); Z remains
relative to the named vertical datum. Transient physics islands may use double
world metres or a cell-local frame, but their transform to WorldPosition is
generation tagged. Rendering uses float offsets from a double high/low
RenderOrigin and carries OriginGeneration. A rebase changes representation,
never physical position, phase, velocity, or saved data.

All engine boundaries use SI: metres, seconds, kilograms, kelvin, radians,
newtons, pascals, joules, watts, metres/second, and kilograms/metre cubed.
Normalized UI values are explicitly dimensionless. Assets record source units,
axis convention, and vertical datum; conversion occurs in the cooker/importer.
The ocean-specific Fourier, optical, acoustic, salinity, and datum conventions
in ocean\87_ocean_conventions_invariants.txt extend this section.

Time and interpolation
----------------------

SimulationClock is the only wall-clock-to-simulation-step authority. The
authoritative time is TickId plus a rational fixed period stored in the world
epoch. FixedDelta is a typed seconds value derived from that period; systems do
not accumulate render delta. A world cannot change its period without an
explicit migration/restart.

RenderInterpolationAlpha is clamped to [0,1) and blends immutable previous and
current simulation snapshots only. It never changes authoritative state,
events, audio scheduling, persistence, networking, physics, weather, ocean, AI,
or gameplay. RenderDeltaSeconds is allowed only for presentation-only effects
whose state cannot feed simulation.

Resource state and Vulkan vocabulary
------------------------------------

VulkanRuntime owns instance, surface, physical/logical device, and queue
handles. CommandScheduler owns each queue's timeline semaphore and monotonically
increasing values. Timeline integers are meaningful only with QueueId; APIs do
not accept an unqualified uint64 completion value.

Every GPU use declares:
    resource generation; queue; pipeline stage; access; image layout if any;
    producer/consumer; and GpuCompletionSet for last use.

RenderGraph is the sole normal-frame authority for pass ordering, barriers,
layout transitions, and queue-family ownership transfers. GpuResourceManager
stores the last compiled state only for validation/import into the next graph;
it does not invent hidden barriers or wait. Resource states use Vulkan
synchronization2 stage/access/layout triples, not ambiguous "ready" booleans.

Memory and ownership vocabulary
-------------------------------

"Owns" means sole destruction responsibility. "Retains" means an explicit RAII
strong reference or lease. "Observes" means a non-owning borrow bounded by the
call or snapshot lifetime. Owning raw pointers are prohibited. Non-owning
pointers/references are permitted only when the signature and lifetime state
the bound; public asynchronous work captures RAII tokens or immutable snapshots.

All published snapshots are immutable and generation tagged. Mutable builders
are thread-confined and become unreadable after publication. Replacement is a
transaction: construct, validate, publish atomically at the documented phase,
and retire the old generation after its CPU readers and GpuCompletionSet finish.

Determinism and seeds
---------------------

    WorldSeed128
    DeterministicStreamKey {
        worldSeed, subsystemId, stableObjectId, TickId, purposeId, drawIndex
    }

Authoritative random values use a versioned counter-based generator. They do
not use global mutable RNG state, wall clock, thread ID, job completion order,
render frame, GPU readback, or container iteration order. Reductions and tie
breaks use stable keys and documented ordering. Saves/network handshakes retain
seed, generator version, epoch, and any required counter/progress state.
Cosmetic randomness uses a separately named VisualSeed and cannot affect
authoritative results.

Thread vocabulary
-----------------

Main thread owns platform callbacks and host orchestration. Simulation thread
is the sole authoritative world writer (initially it may be the main thread).
Render thread builds/submits frames. Job workers transform immutable inputs into
unpublished outputs. I/O work blocks only worker threads. Audio callback thread
is real-time: no allocation, locks, logging, I/O, exceptions, or engine calls.
See FRAME_THREADING_MODEL.txt for phase order and allowed handoffs.

Compatibility and validation
----------------------------

Older names such as OceanSimulation are facade names only where their design
explicitly says so. "FileSystem", "SettingsSystem", untyped "ID", naked
"timeline value", and float world position are not public canonical contracts.
Acceptance requires type-domain compile tests, unit/axis round trips, stale
handle tests, deterministic worker-count replay, origin-rebase invariance,
CPU/GPU convention hashes, and rejection of mixed generations.
