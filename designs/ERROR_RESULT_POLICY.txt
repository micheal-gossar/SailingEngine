CROSS-SYSTEM ERROR, RESULT, AND CALLBACK POLICY
===============================================

Status
------

Normative for public engine and subsystem boundaries. Existing API snippets are
conceptual where they omit Result. New code must not mix exceptions, status,
sentinels, and silent fallback for the same failure class.

Canonical forms
---------------

    Result<T, Error>       expected operation can fail
    Result<void, Error>    fallible command
    Status                 non-failure state such as Pending/NotReady/Skipped
    Poll<T>                Pending | Ready(T) | Failed(Error)

Error is a value containing:
    stable ErrorCode; Severity; subsystem/operation; human diagnostic;
    optional causal Error; EntityId/AssetId/handle/generation/tick/frame/queue
    context as applicable; and backend code without lossy translation.

Public recoverable APIs return Result/Poll. Querying a stale handle, missing
asset, unavailable cell, capacity exhaustion, invalid user/cooked input,
out-of-date swapchain, timeout, and I/O/backend failure are values. A partial
operation either rolls back or documents a committed subset in its result.
Outputs are initialized on failure.

Exceptions and assertions
-------------------------

Exceptions are permitted inside implementation or constructors to unwind RAII,
and in offline tools when caught at the tool operation boundary. No normal
cross-subsystem API requires callers to catch. ApplicationHost, JobSystem task
wrapper, offline AssetCooker operation, and Renderer device-recovery boundary
translate caught exceptions into Error while preserving type/message/context.

Programmer contract violations (impossible phase, unchecked invalid enum,
double consumption, internal invariant) assert in debug and become Fatal Error
at a containment boundary in release. Assertions do not replace validation of
external, cooked, save, network, driver, or user data.

Callbacks and real-time boundaries
----------------------------------

Every Vulkan/GLFW/C/import-library callback is `noexcept`. It validates its
context, copies bounded data if possible, increments an overflow counter if
not, and returns the required ABI status. It never throws, allocates without a
declared callback-safe allocator, blocks, logs recursively, or calls gameplay.
No exception crosses C.

The audio callback is stricter: no allocation, lock, I/O, logging, Result
formatting, engine service call, or exception. It consumes prepared values and
sets atomic telemetry flags only.

Jobs catch all exceptions at the job wrapper. Completion contains Result; Wait
or dependency propagation cannot rethrow across subsystem boundaries. A failed
prerequisite deterministically cancels/degrades dependents according to their
declared policy.

Fallback and degradation
------------------------

A fallback is legal only when its owner, trigger, capability/quality effect,
data provenance, and diagnostic are documented. Result reports Degraded plus a
reason; it never returns a ready-looking substitute. Authoritative simulation
cannot use render/GPU readback, zeroed missing bathymetry, unrelated placeholder
assets, or a changed deterministic seed as fallback.

Named default render/audio/UI assets are explicit AssetIds and may replace only
presentation data. Last-known-good generations may be held when their age and
confidence are exposed. Missing required physics/save/network data fails world
activation or the affected transaction.

Error propagation and containment
---------------------------------

Preserve the original backend code and causal chain. Add context once per
boundary; do not log and rethrow repeatedly. The owner decides retry, degrade,
rollback, quarantine, or fatal exit. Diagnostics observes an Error but is not
required for correctness and diagnostics failure never masks the original.

Transactions use Prepare -> Validate -> Commit -> Publish. Failure before
Publish leaves the old generation authoritative. Failure after an externally
visible commit must return a compensation/recovery state; "best effort" without
a status is prohibited.

Device lost invalidates GPU handles/plans and may retain CPU simulation.
Corrupt save/cooked/network input is bounded before allocation and cannot
partially mutate live state. Out-of-date/suboptimal/zero-extent presentation is
status, not an exception. Capacity errors apply documented back-pressure or
stable-priority dropping only for optional data.

Error namespaces
----------------

Shared codes cover InvalidArgument, InvalidHandle, StaleGeneration,
InvalidPhase, Cancelled, Timeout, NotReady, CapacityExceeded, BudgetExceeded,
Unavailable, CorruptData, VersionMismatch, DependencyFailed, BackendFailure,
DeviceLost, InvariantViolation, and ShuttingDown. Subsystems add typed codes;
callers may branch on stable codes, never diagnostic strings.

Acceptance
----------

Each design tests invalid arguments, stale handles/generations, cancellation,
capacity/budget, dependency failure, rollback, last-known-good behavior,
diagnostic failure, and shutdown. ABI tests throw deliberately inside callback
adapters and prove containment. Fault injection covers allocation, I/O, shader/
pipeline creation, queue submission, save replacement, job failure, device
loss, and fallback provenance.
