COLLISION SYSTEM CLASS DESIGN
=============================

Class:

    CollisionSystem

Purpose:

    Own immutable collision shapes, layer/filter policy, broadphase metadata, and mesh cooking used by PhysicsWorld.

Public API:

    CreateShape(desc)->Result<ShapeHandle,CollisionError>;
    CookMesh(mesh,cookOptions)->Future<Result<ShapeHandle,CollisionError>>;
    SetLayerRule(a,b,enabled);
    Filter(query,object);
    ShapeBounds(handle);
    InvalidateAsset(assetId);

Internal state and components:

    - shape cache by content hash.
    - convex/triangle/compound data.
    - collision layers/masks.
    - cooking queue.
    - material metadata.

Lifecycle and ownership:

    ShapeHandle shared RAII; PhysicsWorld retains handles while bodies exist; cooked backend resource destroyed after last body and physics safe point

Error behavior:

    Invalid/corrupt/unbounded geometry, stale handle, unsupported shape,
    capacity, cancellation, and backend failure return CollisionError. Failed
    cooking publishes no cache entry.

Threading and timing constraints:

    shape creation/cooking jobs off simulation thread; backend insertion at step boundary; filter table immutable during Step

Dependencies:

    - Collision mesh value/format schemas.
    - JobSystem.

Tests:

    - primitive bounds.
    - layer matrix.
    - convex limits.
    - corrupt/nonmanifold mesh.
    - cache reuse.
    - body retains shape.
    - async cancellation.

Implementation rules:

    - Keep implementation-only types out of public headers.
    - Use RAII and generational IDs; do not expose owning raw pointers.
    - Validate descriptions before allocating or mutating state.
    - Publish complete snapshots/generations rather than partially updated data.
    - Add diagnostics for failure context without making logging a dependency
      of correctness.

Canonical integration contract:

    Normative immutable ShapeHandle owner. PhysicsWorld retains handles and
    consumes backend shape payloads; CollisionSystem has no PhysicsWorld
    dependency. Runtime cooking consumes validated CPU mesh values, not
    MeshSystem GPU objects. Offline AssetCooker invokes a separate collision
    processor interface and does not enter runtime ownership. Shape destruction
    waits for retained bodies and the P7 safe boundary.

    See INDEX.txt, 24_physics_world.txt, and ..\assets\44_asset_cooker.txt.
