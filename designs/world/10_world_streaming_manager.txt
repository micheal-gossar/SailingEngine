WORLD STREAMING MANAGER CLASS DESIGN
====================================

Class:

    WorldStreamingManager

Purpose:

    Own the global observer set and desired world-cell residency plan, prepare
    participant cell work asynchronously, atomically activate complete cells,
    and unload distant cells within CPU/GPU/I/O budgets.

Public API:

    Result<ObserverToken,StreamingError> AddObserver(
        ObserverId, const StreamingObserver&);
    void UpdateObserver(ObserverId, WorldPosition);
    void RemoveObserver(ObserverId id);
    void UpdatePriorities(TickId);
    Result<void,StreamingError> CommitAtTickBoundary(TickId);
    RegistrationToken RegisterParticipant(IWorldCellParticipant&);
    bool IsCellReady(WorldCellId id) const;
    StreamingStatistics Statistics() const;

Cell states:

    Unloaded
    Requested
    Loading
    WaitingForDependencies
    ReadyToActivate
    Active
    PendingUnload
    Failed

Cell contents:

    Terrain chunks.
    Static render instances.
    Collision.
    Navigation data.
    Ports and moorings.
    Audio zones.
    Gameplay spawn definitions.
    Each content kind is owned by its registered participant; the manager owns
    plan/leases/state transaction only.

Selection:

    Convert observer position to cell coordinates.
    Determine required, preload, and retention radii.
    Prioritize by distance, travel direction, and cell importance.
    Respect maximum concurrent I/O and upload work.

Activation:

    Activate only after required assets, collision, and render data are ready.
    Publish cell entities at a safe synchronization point.
    Roll back partial activation after failure.

Unloading:

    Ask participants for immutable dirty save fragments.
    Remove gameplay entities.
    Remove physics/navigation data.
    Release assets.
    Defer GPU resource destruction.

Rules:

    No blocking file I/O on simulation/render threads.
    Failed cells expose explicit diagnostics.
    Active cells never reference unloaded dependencies.
    Requests are cancellable before activation.
    Public positions use canonical WorldPosition; no rebased float position is
    authoritative.

Tests:

    Load/activate nearby cell.
    Cancel cell moving out of range.
    Shared assets survive one cell unloading.
    Failure rolls back partial state.
    Budget enforcement.
    Multiple observer union.
    Rapid boundary movement without thrashing.

Dependencies:

    AssetManager
    JobSystem
    Registered IWorldCellParticipant interfaces

Canonical integration contract:

    Normative sole global residency/observer/budget owner. TerrainSystem,
    NavigationGraph, OceanStreamingService, gameplay/entity/physics cell
    loaders, audio zones, and render data register participant callbacks that
    prepare privately and commit/rollback at P3. OceanStreamingService may
    refine ocean content priority inside an admitted WorldCellLease but cannot
    create a second global observer policy.

    WorldCellId/lease is a typed generation; positions are WorldPosition.
    Jobs/I/O never mutate live state. SaveSystem consumes participant snapshots
    at P11 and is not a streaming dependency. See ..\FRAME_THREADING_MODEL.txt,
    ..\OWNERSHIP_LIFETIME_SHUTDOWN.txt, and INDEX.txt.
