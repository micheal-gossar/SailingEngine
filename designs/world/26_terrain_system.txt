TERRAIN SYSTEM CLASS DESIGN
===========================

Class:

    TerrainSystem

Purpose:

    Stream, render, and query island/seabed terrain chunks with consistent LOD and collision data.

Public API:

    RequestChunk(key,lod);
    ReleaseChunk(key);
    Update(WorldPosition observer);
    BuildDraws(view);
    SampleHeight(WorldPosition);
    GetCollisionMesh(key);
    OnRenderOriginChanged(RenderOrigin);

Internal state and components:

    - chunk state machine.
    - height/mesh data.
    - quadtree LOD.
    - GPU mesh handles.
    - collision handles.
    - seam/skirt metadata.
    - material layers.

Lifecycle and ownership:

    streaming manager owns requests; terrain owns active chunk resources; CPU source retained per policy; GPU deletion deferred

Error behavior:

    Invalid/stale chunk/lease, missing/unknown datum or no-data, asset/cook/
    collision/upload/budget failure returns TerrainError. SampleHeight returns
    Unavailable with generation/confidence; unknown terrain is never zero.

Threading and timing constraints:

    I/O/cooking on jobs; activation at P3; draw list on render thread; CPU uses
    WorldPosition/double local metres and GPU uses float relative position plus
    OriginGeneration.

Dependencies:

    - WorldStreamingManager participant/WorldCellLease interface.
    - AssetManager.
    - MeshSystem.
    - MaterialSystem.
    - CollisionSystem.
    - BathymetryPipeline snapshots for seabed/coast content.

Tests:

    - LOD neighbor seam.
    - height sample.
    - missing tile.
    - cancellation.
    - collision/render alignment.
    - origin shift.
    - budget eviction.

Implementation rules:

    - Keep implementation-only types out of public headers.
    - Use RAII and generational IDs; do not expose owning raw pointers.
    - Validate descriptions before allocating or mutating state.
    - Publish complete snapshots/generations rather than partially updated data.
    - Add diagnostics for failure context without making logging a dependency
      of correctness.

Canonical integration contract:

    Normative terrain chunk owner and streaming participant. P3 atomically
    publishes matching render/collision/height/bathymetry-facing generations;
    consumers pin immutable snapshots. CPU queries use WorldPosition/double SI
    and named vertical datum; GPU packets use relative float plus
    OriginGeneration. Render skirts never change collision, bathymetry, or
    navigation height. GPU replacement retires through GpuCompletionSet.

    See INDEX.txt, ..\ocean\89_bathymetry_pipeline.txt,
    ..\CANONICAL_CONVENTIONS.txt, and ..\vulkan\20_frame_manager.txt.
