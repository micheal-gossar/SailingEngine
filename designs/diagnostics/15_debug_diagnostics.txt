DEBUG DIAGNOSTICS CLASS DESIGN
==============================

Class:

    DebugDiagnostics

Purpose:

    Centralize structured logs, Vulkan validation messages, CPU/GPU timings,
    counters, resource names, and captured error context.

Public API:

    void Log(LogSeverity severity, LogCategory category, std::string message);
    DiagnosticScope BeginScope(std::string_view name);
    CounterHandle RegisterCounter(std::string_view name);
    void SetCounter(CounterHandle counter, double value);
    std::vector<DiagnosticMessage> SnapshotMessages() const;
    DiagnosticsSnapshot Snapshot() const;

Vulkan integration:

    Provide VkDebugUtilsMessenger callback storage.
    Store severity, type, message ID/name, text, and related objects.
    Return VK_FALSE from callbacks.
    Never throw through a C callback.
    Expose sequence numbers so initialization/render operations can associate
    new messages with the active operation.

DiagnosticScope:

    Records start/end CPU timestamps.
    Maintains parent/child scope relation.
    Adds operation name to exceptions/log messages.
    Is move-only and ends automatically on destruction.

GPU diagnostics:

    Allocate timestamp query ranges per frame.
    Insert debug labels into command buffers.
    Resolve results after frame completion.
    Display pass timings and queue overlap.

Counters:

    Frame time.
    Draw calls.
    Triangles.
    Active entities.
    Loaded assets.
    Streaming backlog.
    GPU/CPU memory.
    Ocean sample count.
    Physics body count.

Threading:

    Producers may log from worker threads.
    Use bounded queues or controlled allocation.
    Snapshot copies stable data for UI.
    Overflow is counted and reported, not silently ignored.

Rules:

    Diagnostics failure must not crash a Release build.
    Fatal engine errors retain original exception context.
    Sensitive/unbounded binary data is not logged.
    Resource labels are enabled only when supported.
    Assertions remain distinct from recoverable errors.

Tests:

    Multi-threaded message recording.
    Scope nesting and duration.
    Vulkan callback conversion.
    Sequence-range association.
    Queue overflow reporting.
    Counter registration/update.
    GPU timing delayed resolution.

Dependencies:

    None at core logging/counter/snapshot level.
    VulkanRuntime/FrameManager adapters publish validation/timing values.
    DevelopmentUI consumes DiagnosticsSnapshot; no reverse dependency.

Canonical integration contract:

    Normative foundational observer, never a correctness/ownership dependency.
    Core diagnostics exists before Vulkan/window subsystems and outlives them.
    Producers enqueue bounded structured values with stable category/code,
    TickId/RenderFrameId/handle/generation where relevant. Overflow is counted.
    C/Vulkan callbacks are `noexcept`, use callback-safe bounded storage, and
    return backend-required status without invoking UI/logging recursively.

    GPU query allocation/lifetime stays in FrameManager/RenderGraph adapters;
    diagnostics receives delayed results only. DevelopmentUI reads snapshots
    and can mutate engine state only by validated commands. See
    ..\ERROR_RESULT_POLICY.txt and ..\OWNERSHIP_LIFETIME_SHUTDOWN.txt.
