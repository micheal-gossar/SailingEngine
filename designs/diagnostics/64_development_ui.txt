DEVELOPMENT UI CLASS DESIGN
===========================

Class:

    DevelopmentUI

Purpose:

    Expose diagnostics, inspectors, render graph views, console commands, and safe debug edits in development builds.

Public API:

    RegisterPanel(id,drawFn);
    RegisterCommand(schema,handler);
    Toggle();
    Update(snapshot);
    BuildDrawData();
    Execute(text);
    Selection();

Internal state and components:

    - panel registry.
    - console history/parser.
    - entity selection.
    - diagnostics snapshots.
    - graph/resource inspectors.
    - edit command queue.

Lifecycle and ownership:

    compiled/disabled by build option; panel registrations RAII; UI stores IDs not mutable engine pointers

Error behavior:

    Invalid panel/command/schema/selection, stale EntityId, parse, capacity, or
    command rejection returns DevelopmentUIError. Draw/diagnostic failure cannot
    change engine operation.

Threading and timing constraints:

    main/render UI thread; inspectors read snapshots; edits become validated gameplay/settings commands at safe points

Dependencies:

    - UISystem.
    - DebugDiagnostics.
    - EntityRegistry.
    - RenderGraph.
    - ConfigurationSettings.

Tests:

    - command parsing.
    - unknown command.
    - panel unregister.
    - stale selected entity.
    - edit routing.
    - release-build disabled behavior.

Implementation rules:

    - Keep implementation-only types out of public headers.
    - Use RAII and generational IDs; do not expose owning raw pointers.
    - Validate descriptions before allocating or mutating state.
    - Publish complete snapshots/generations rather than partially updated data.
    - Add diagnostics for failure context without making logging a dependency
      of correctness.

Canonical integration contract:

    Development-only presentation consumer. It retains DiagnosticsSnapshot,
    RenderGraph inspection values, and typed IDs—not subsystem pointers. Panels
    execute on UI thread outside registry locks. Every edit is a schema-validated
    GameplayCommand or ConfigurationSettings transaction applied at the normal
    safe point; no inspector writes mutable ECS/GPU/world state.

    See 15_debug_diagnostics.txt, ..\ui\36_ui_system.txt,
    ..\gameplay\59_gameplay_command_bus.txt, and
    ..\FRAME_THREADING_MODEL.txt.
